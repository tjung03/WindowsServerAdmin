# Active Directory 실습 구조

[저장소 소개](../README.md)

## 노트에 기록된 구성 순서

| 단계 | 대상 | GUI에서 선택한 내용 | 선행 조건 |
|---|---|---|---|
| 1 | FIRST | 서버 관리자에서 AD DS 역할 추가 → 새 포리스트 `hanbit.com` → DNS·GC 선택 | `192.168.10.10/24` 및 DNS 주소 확인 |
| 2 | SECOND | AD DS 역할 추가 → 기존 포리스트에 자식 도메인 `second.hanbit.com` 추가 | FIRST의 DNS로 조회 가능해야 함 |
| 3 | THIRD | AD DS 역할 추가 → 기존 `hanbit.com` 도메인에 RODC 추가 | FIRST 도메인 연결 및 DNS 확인 |
| 4 | WinClient | DNS 서버를 FIRST로 지정 → `hanbit.com` 도메인 가입 | 도메인 이름 조회와 인증 정보 필요 |

노트에는 FIRST·SECOND·THIRD의 주소가 각각 `192.168.10.10`, `.20`, `.30`으로 기록되어 있습니다. 도메인 멤버의 IP 주소는 적혀 있지 않습니다. FIRST의 DNS 주소를 사용하는 설명은 당시 실습 구성에 한정됩니다.

## GUI 확인 지점

- 서버 관리자 → **역할 및 기능 추가**: 대상 서버와 `Active Directory Domain Services` 역할을 확인합니다.
- AD DS 구성 마법사: FIRST는 **새 포리스트**, SECOND는 **기존 포리스트의 새 도메인**, THIRD는 **기존 도메인의 추가 DC와 RODC** 선택을 구분합니다.
- WinClient의 시스템 설정: 도메인 가입 후 소속 도메인과 DNS 서버 주소를 확인합니다.
- DNS 관리 도구: `hanbit.com`과 자식 도메인의 이름 조회 결과를 확인합니다.

위 항목은 **노트의 수행 절차를 검토 가능한 체크포인트로 재구성한 것**입니다. 현재 VM에서 직접 재실행하거나 결과를 수집한 기록은 이 저장소에 없습니다. RODC 암호 복제 정책, 복제 정상 상태, 장애 전환은 노트의 토폴로지만으로 검증되었다고 볼 수 없습니다.

## 자료의 경계

노트에는 OU·사용자·그룹과 제어판 제한·그룹 정책 상속 실습 항목도 있습니다. 이 문서에서는 서버 세 대와 클라이언트 한 대의 AD 실습 구조에 직접 연결되는 범위만 간추렸습니다. GPO 적용 결과나 조직 단위 설계를 새로 만들어 넣지 않았습니다.
