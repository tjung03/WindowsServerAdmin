# AD DS 구성 관계와 확인 지점

[저장소 소개](../README.md)

`ad.example.test`와 `child.ad.example.test`는 논리 구성 설명용 이름입니다. 실제 도메인과 서버 주소는 대상 실습 환경에서 별도로 정합니다.

| 단계 | 역할 | 구성 흐름 | 확인할 것 |
|---|---|---|---|
| 1 | 첫 도메인 컨트롤러 | AD DS 역할 설치 → 새 포리스트 `ad.example.test` 생성 → DNS 구성 | 서버의 주소·DNS 설정, 도메인과 DNS 존 |
| 2 | 자식 도메인 컨트롤러 | 첫 서버를 DNS로 조회할 수 있게 설정 → 기존 포리스트에 `child.ad.example.test` 추가 | 부모·자식 도메인 조회와 DC 등록 |
| 3 | RODC | 기존 도메인에 읽기 전용 도메인 컨트롤러 추가 | 역할 속성, 이름 조회와 복제 상태 |
| 4 | 클라이언트 | 도메인 DNS를 사용해 `ad.example.test`에 가입 | DNS 응답, 도메인 소속과 로그인 결과 |

## GUI 및 결과 확인

- **서버 관리자 → 역할 및 기능 추가:** 대상 서버와 AD DS 역할 설치 상태를 확인합니다.
- **AD DS 구성 마법사:** 새 포리스트, 기존 포리스트의 자식 도메인, 기존 도메인의 추가 DC와 RODC 선택을 구분합니다.
- **DNS 관리자:** 부모·자식 도메인의 존과 필요한 DC 레코드를 확인합니다.
- **클라이언트 설정:** 도메인 가입 전에 DNS 서버와 이름 조회를 확인하고, 가입 후 도메인 소속과 로그인을 확인합니다.

역할 설치 화면만으로 DNS 정상 응답, 복제 상태 또는 클라이언트 인증 성공을 증명할 수 없습니다. 각 단계의 결과는 실제 환경에서 별도로 수집해야 합니다. RODC의 암호 복제 정책이나 장애 전환은 이 구성 관계만으로 검증되지 않습니다.
